Decisiones que cambiaron el producto

Cuatro decisiones que no son obvias

  • El SKU es inmutable. El comercio puede tenerlo impreso en una etiqueta; cambiarlo rompe una referencia que ya existe fuera del sistema.
  • Nada se borra de verdad. Dar de baja marca active=false. Una eliminación accidental es reversible.
  • El token de acceso vive solo en memoria. El almacenamiento local es legible por cualquier script inyectado: un XSS se vuelve robo de sesión.
  • Los errores son datos. RFC 7807 con un type estable. El cliente reacciona al código, nunca al texto.

Cada una tiene una alternativa que se consideró y se descartó por escrito. Sin el motivo escrito, dentro de seis meses nadie recuerda por qué se hizo así.

Sesión y seguridad

Un fallo que costó una sesión legítima

1

El acceso expira a los 15 min.
Varias peticiones fallan a la vez.

2

Cada una dispara su propia renovación con el mismo token.

3

El token es de un solo uso: la segunda se lee como reutilización maliciosa.

4

La familia de tokens queda revocada. Sesión legítima muerta.

La corrección no fue un parche: fue coalescer las renovaciones en una sola operación en vuelo. Es un bug que solo aparece cuando el sistema se usa de verdad —y por eso la demostración en vivo importa.
